# M2 子功能 · 授权前试选

在[进化路线](../ROADMAP.md)的「记住我的选择，备好下一部」阶段使用。这里的候选指允许订阅的库外电影。[M1 个人今晚选片](movie-night.md)从本人已经有权观看的库内电影开始。

**要解决的问题**　用户看到「每天最多 3 部」和上一轮的计数，仍要先授权，才能知道助手究竟会替自己选哪几部。这次交付让他先看到实际片名，再作决定。

## 用户走一遍

1. 管理员已选定一个 Emby 用户及媒体库，并授权读取其画像；已有新鲜候选。订阅设置和电影目录已具备校验条件，此时可以尚未授权自动订阅。
2. 在同一处查看订阅范围并点「试选」。结果最多显示当日剩余额度对应的三张小卡，列出片名、真实口味匹配分和选中依据。同一处简短交代检查了几部、为什么顺延。查不到时显示缺的条件和设置入口。
3. 想继续就核对范围并主动授权；也可以关闭。以后按原计划自动运行。预览标注生成时间，片单、额度或媒体库变化时，以执行时的重新核对为准。

## 开发顺序

- [ ] **先写合同测试。** 用同一份虚构数据覆盖第一名已有订阅、随后三部符合条件的例子。另测当天只余一个名额、画像未授权、片单失效、低磁盘空间以及查重服务超时。结果不足三部按实显示，超出检查预算的作品标记为尚未核对。
- [ ] **接出只读路径。** 在已保存且与绑定范围相符的配置上试选。复用现有候选评分、查重、当日额度、磁盘和订阅范围规则；读取候选、配置和执行记录的快照。重复点击也不得改变授权、额度、游标、正式运行的上轮统计或下载状态。沿用正式执行的单轮核对预算，按需请求，一次最多一个进行中的试选。
- [ ] **接入现有看板与设置。** 用户主动点试选才计算；同一窗口就能看到结果、处理缺项、决定是否授权。桌面和手机各验收一次。已授权的实例能试选剩余额度，不触发额外一次正式调度。
- [ ] **验证再交给维护者试用。** 在隔离的 2.15.6 验证未授权点两次试选后订阅和下载仍为 0。用可控输入验证预览后若已有订阅、磁盘不足或授权变化，执行时能跳过或暂停。记录验证结果和已知限制，回到 [路线图](../ROADMAP.md) 更新「当前接力」。

## 代码入口与边界

| 入口 | 用途 |
| --- | --- |
| [执行策略](../plugins.v2/ptsubtitlefollowup/fusion/execution.py) | 从 `_eligible`、`preflight` 和额度计算开始阅读。`preflight` 只验证条件。提取可复用的纯计算或只读判定，避免维护两份排序 |
| [订阅与媒体库适配](../plugins.v2/ptsubtitlefollowup/fusion/subscription_host.py) | 复用 `lookup_subscription` 和 `lookup_library`，遵守对应策略的查重边界；无编号且使用别名的影片仍可能重复 |
| [插件接口](../plugins.v2/ptsubtitlefollowup/__init__.py)、[配置交互](../frontend/config.js) | 沿用管理员身份校验和显式范围确认。媒体读取授权与创建订阅授权分开处理 |
| [执行回归](../tests/test_execution.py)、[配置交互回归](../tests/config_flow.cjs) | 对比预览前后的持久状态；对订阅新增、下载及调度入口断言调用次数为零 |

不要直接调用 `tick`、`_scan`、`_dispatch` 或 `authorize` 来模拟试选。现有的部分 `status()` 路径会同步状态或撤销失效的授权，也要核实后再复用。首次打开插件、加载设置、预览等操作都不能代替用户授权。生产 NAS 上的安装与真实订阅不属于开发验收。
