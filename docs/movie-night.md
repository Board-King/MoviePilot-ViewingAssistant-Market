# M1 开发说明 · 一个人今晚看什么

**目标体验**　用户今晚只有 90 分钟。打开观影助手，勾选需要中文字幕，通过最多三部库内推荐选中一部，进入自己有权访问的 Emby 条目开看。该体验优先验证个人决策与实际播放。[阶段目标与试用门槛](../ROADMAP.md)

## 用户走一遍

1. 用户在 MoviePilot 里打开自己的看板，已绑定一个经过核实的 Emby 用户和明确授权的库范围。绑定不完整时提示去哪里完成配置，不能借用其他用户的偏好或管理员能看到的全部库。
2. 选时长上限和是否需要中文字幕，主动请求片单。条件都可跳过。已有可用个人画像时，优先选有口味依据的作品；没有有效画像时不能展示个人匹配分。若实现支持按已授权条件选片，应把这种推荐与个性化推荐区分开。
3. 每张卡只呈现决定是否开看需要的事实。片名、已知时长、已确认的中文字幕和可证实的匹配理由优先。同一推荐同时满足指定条件；候选不足时按实显示。资料不足、服务不可用和条件内没有结果分开提示。
4. 点击「打开 Emby」后，由 Emby 按当前登录身份核对权限。页面跳转与实际开播分别记录。选片在自动订阅关闭时也应工作，不占额度，不创建订阅或下载任务。

## 验收清单

| 场景 | 可以核对的结果 |
| --- | --- |
| 个人身份与范围 | 在隔离环境准备两个权限不同的用户和两个库；验证单次请求只返回当前绑定用户已授权库里的电影。切换绑定、缩小库范围或撤销权限时旧结果失效。前端看不到服务端 Emby 密钥、管理员凭据和文件路径 |
| 真实选片 | 对 90 分钟上限验证小于、等于、大于以及时长未知的电影；有严格时长要求时排除未知。口味理由用已授权画像中真实的匹配特征，没有证据就留空。排除已知不可观看的虚拟或缺失条目 |
| 中文字幕与版本 | 当用户要求中文字幕时，只用能关联到同一媒体版本的已识别字幕轨或已核实的侧车结果。片长和字幕不能从不同版本拼出一个推荐。只有文件名提示、原发布页有字幕、补查仍在等待，均不能算作已确认。STRM 有 Emby 条目也不能据此保证云端媒体可播放 |
| 交互与开播 | 在手机和桌面验证正常、空结果、权限失效和超时；快速改条件时只呈现最后一次有效请求的结果。用经验证的地址打开正确条目，无法生成安全可达的入口时给出明确提示。用户自愿确认或经授权的播放证据才能计入实际开播 |
| NAS 开销 | 只在主动选片时取数，给读取时间、页数及条数设上限。大库未读全时明确本次覆盖范围；多次打开看板不触发反复扫描全库或逐个探测云端文件。验证本地文件和 STRM 各一个，自动订阅关闭时副作用为零 |

开发先读[插件接口](../plugins.v2/ptsubtitlefollowup/__init__.py)、[现有 Emby 连接](../plugins.v2/ptsubtitlefollowup/fusion/emby.py)和[偏好计算](../plugins.v2/ptsubtitlefollowup/fusion/profile.py)。原有[候选来源](../plugins.v2/ptsubtitlefollowup/fusion/source_registry.py)以外部片单为主，不能把库外候选当成库内可看电影。本阶段的入口服务于已绑定的个人用户。家庭二维码、投票和多人身份属于[后续验证假设](../ROADMAP.md)。

## 首批个人试用

找 10 位已经用 MoviePilot 和 Emby 的个人用户。各自按原来的方式和新版各选一次，记录「打开到定片」和「定片到实际开播」；有两次机会时可交错顺序，注明是否原本就知道想看什么。按人去重，第 2 周结束后核对是否有 6 人完成首次开播、4 人在无人提醒时主动再用。缺少回访标为未报告；样本不足时先记录实际人数和阻碍。收集用户为什么选或跳过、哪一步打开失败，公开仓只保存虚构示例或匿名汇总。
