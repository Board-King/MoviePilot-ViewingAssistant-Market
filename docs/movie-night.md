# M1 开发说明 · 今晚看什么

**交付物**　一个家人愿意从手机再打开的局域网观影入口。演示从普通成员拿起手机开始，到在 Emby 里播出一部符合条件的电影为止。测试包使用虚构家庭和有权用于演示的样片。版本目标与试用门槛见[路线图](../ROADMAP.md)。

## 看得见的体验

1. 管理员一次配置可用于选片的 Emby 服务器和电影库。成员使用独立身份或已经验证的家庭参与机制打开手机页面。第一屏给出「今天有多久」「是否需要中文字幕」两个可跳过的选择。未授权个人画像时也能使用可见片库及显式条件。
2. 只从这位成员可见的库内电影中挑选最多三部，同一作品的多个版本归到一张卡。卡片突出海报、片名、时长和所选版本的字幕依据。条件不齐全时直接告诉用户可以放宽哪一项；不能用未经证实的记录凑足三部。
3. 单人可以直接前往 Emby。两人参与则各自点想看，同一场选择仅展示两人都可见的作品；不公开各自观看史。没有交集时可以更换选项。成员选择不写入另一人的口味画像。
4. 播放交给客户端原有的身份和权限。区分「已打开 Emby」和「已开始播放」。首批试用允许用户自愿确认是否播出，确认事件与跳转点击分开计数。无需为了试用启用自动订阅或上传观影数据。

## 接手顺序

| 顺序 | 开发与验收 |
| --- | --- |
| 1 · 最大风险 | 先审查[现有插件路由](../plugins.v2/ptsubtitlefollowup/__init__.py)和 [Emby 连接](../plugins.v2/ptsubtitlefollowup/fusion/emby.py)。在隔离环境验证普通成员的访问方式、在手机上打开 Emby 条目的真实路径，以及单台实际播放端的行为。两账号有不同库权限，不能读到对方独有的影片、缩略图或记录。不得向前端分发 MP 管理员凭据、服务端 Emby 密钥或媒体直链。若无法安全验证成员访问，先交付同屏轮流选择原型，标明手机独立入口仍未达标 |
| 2 · 一个人能开看 | 现有[候选来源](../plugins.v2/ptsubtitlefollowup/fusion/source_registry.py)以外部片单为主。增加按用户与授权库隔离的库内候选投影，仅取所需字段并限制读取量。复用[口味规则](../plugins.v2/ptsubtitlefollowup/fusion/profile.py)；不读取其他家庭成员的记录。时长来自版本元数据，已识别的中文字幕来自该版本的字幕轨或能可靠关联的侧车记录。只有站点提供过字幕、只有文件名提示或字幕尚在补查时，标为未知。严格字幕筛选只使用已确认结果 |
| 3 · 两个人能定片 | 在同一入口加有期限、可结束的家庭场次；处理相同选择、不同选择、刷新重进、退出和失效。若启用二维码，只包含临时参加信息。海报、候选、开播目标均核对权限；多人场次复核所有参与者共同可见范围。默认不开放公网 |
| 4 · 让别户能试 | 用本地影片及 STRM 各验证一部，覆盖字幕缺失、片长未知、媒体离线、客户端无法跳转、账号切换和撤销授权。用小片库与大规模虚构条目检查翻页、内存和响应时间；避免每次打开就扫描全库或探测所有云端文件。为 2.15.6 做升级回归，另选试用者使用的一个目标宿主做安装/只读冒烟。提交支持矩阵、虚构演示、剩余限制和可选的本地试用记录 |

**第一次合并应当能演示**　虚构家庭用两个不同权限账号，在手机进入各自允许的片库，点一部电影正确交给 Emby；无法打开要给出可操作原因。完成后继续做片单和共选，直到整场电影夜可用。单独做三个按钮或调整海报样式，不计为本阶段完成。

## 试用与复盘

邀请符合条件的家庭分别用原来的方式和新版选片，记「拿起手机到定片」与「定片到实际开播」两段耗时。能做两场时交错试用顺序，并记录是否早已决定片名。按家庭记录成败、字幕核对是否正确、是否需要管理员接手、第二周是否主动回来。保留时间差和样本数，单场更快只能作为线索；未报告与明确失败分开。若独自观看占多数，保留单人入口并重新评估共选投入。试用结果由维护者自愿匿名汇总，不把业务数据、诊断包或家庭截图提交到公开仓。
