# 个人选片记忆 · 0.7.1

**场景**　今晚挑出了三部电影，有一部想周末再看，一部不感兴趣。点过后下次选片不再重复推这两部；周末从「留到下次」找到想看的电影，打开 Emby。

## 用户走一遍

1. 沿用已经验证的 Emby 绑定，在「今晚看什么」点「帮我挑片」。
2. 推荐卡直接提供「留到下次」与「不感兴趣」。保存成功后反馈结果并提供「撤销」，失败时保留原卡以便重试。
3. 「留到下次」集中查看保存的电影；「已略过」可恢复推荐。操作都在选片区域完成，不增加设置，不代替用户开启自动订阅。
4. 再次查看片单时读取 Emby 当前权限、观看状态与影片资料。影片已移走或不可见时不展示旧的私有资料。

## 行为边界

- 选择只作用于具体作品。沿用已核实的作品编号去重，没有编号时使用本机 Emby 条目 ID，不凭片名猜测同一作品。
- 记录与服务器、用户及授权媒体库范围绑定；变更绑定会隔离旧记录，返回原绑定可继续使用。关闭功能后不能继续提交旧页面的选择。
- 本版仅影响「今晚看什么」的库内选择。库外候选与自动订阅接入个人反馈属于后续工作，现有订阅及授权不因一次个人选择而改变。
- 记录只在本机保存所需的标识与选择，不存播放地址、访问密钥或完整观看历史。存储有明确上限，达到上限时提示整理记录，不悄悄丢弃旧选择。
- 不自动扫描全库，不监听播放。打开插件本身不会读取电影；读取片单与保存选择由用户操作触发。进入 Emby 的链接点击不计为已开播。

## 实现约定

已保存片单按 ID 读取当前条目。在选定媒体库模式下，再通过绑定用户的祖先目录核实所属库；不能只因请求同时传入 `Ids` 和 `ParentId` 就假定响应满足两者交集。读取受单次时限和每页数量约束。[Emby Items 接口](https://dev.emby.media/reference/RestAPI/ItemsService/getUsersByUseridItems.html) · [Emby 祖先目录接口](https://dev.emby.media/reference/RestAPI/LibraryService/getItemsByIdAncestors.html)

浏览器提交选择时只带服务端签发的短期回执、条目 ID 和动作。服务端核对当前绑定、条目来源和选择版本；过期页面、旧账号页面及过时的撤销不能覆盖较新的选择。选择存储与画像、订阅授权和额度分开，写入失败不能伪装为成功。

本机选择存储使用 `fusion_choices_v1`，每个绑定范围最多 200 条，最多保留 16 个非空范围，清空后的范围会释放。片单每页 12 部，临时回执有效期 15 分钟。超过容量时由用户整理，不自动淘汰；临时回执过期时刷新片单即可。插件重载保留选择并废弃旧回执。

## 验收与接力

开发验收使用虚构账号、片名与媒体库，覆盖保存后重载、同一影片重复版本、恢复与撤销、多标签页过期操作、权限缩减和存储失败。桌面与窄屏验证同一区域内能连续完成操作，读屏和键盘能找到结果与下一步。

实际试用观察两件事：下一次是否能找回留下的电影，以及恢复或略过是否符合预期。M1 的真实开播、STRM 可播放性与次周复用仍须自愿试用确认。本版开发完成不能替代这些使用证据。
